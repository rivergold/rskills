# Review + Explain

对当前分支相对于目标分支的修改进行审查。

## Review

- 检查正确性、并发、性能和资源管理。
- 追踪必要的上下文和调用链。
- 给出问题的文件、行号和严重程度。
- 说明问题成立的条件及修复方案。
- 不报告没有证据支持的问题。

## Explain

- 总结本次修改的目的。
- 讲解主要执行流程。
- 解释重要类和函数的职责。
- 说明关键技术原理。
- 解释架构设计与技术取舍。
- 对复杂算法给出必要的数学解释。

## Rules

- 使用中文。
- 优先分析实际风险。
- 避免琐碎的代码风格建议。
- 不修改代码。
- 将已验证问题与推测风险分开。
